# 同传语言路由台 · 译员交接版

面向国际会议同传负责人的现场调度台。主讲人切换语种或译员临时离席时，调度台立即重算路由，直观显示哪些听众频道还能正常收听、哪些中断以及原因。

**交接版**在"路由表（配置态）"与"音频通道（播放态）"之间加入了一层按**语言通道 × 音频片段边界**生效的译员交接状态机：主译员短暂断线时，路由表可以立刻切换，但音频只在片段边界经过 `准备 → 切换 → 确认` 后才改派；断线被整段吸收、确认迟到、重复恢复等异常都不会造成两条通道同时播放，确认失败可自动回退，全程可观察、可恢复、可撤销。

全部数据在浏览器本地运行，无任何后端依赖。

## 快速开始

```bash
npm install        # 安装依赖（需要 Node.js ≥ 18）
npm run dev        # 开发模式，默认 http://localhost:5173
npm test           # 运行全部测试（vitest）
npm run build      # 类型检查 + 生产构建，输出到 dist/
npm run preview    # 本地预览生产构建
```

## 内置演示场景

打开即是预设会议：**中文主讲**，需要**英语、法语、日语**三个听众频道。

| 译员 | 方向 | 容量 | 初始状态 |
| --- | --- | --- | --- |
| 王（主力） | 中 → 英 | 3 席 | 在线 |
| 李 | 英 → 法 | 1 席 | 在线 |
| 佐藤 | 英 → 日 | 1 席 | 在线 |
| 陈（备援） | 中 → 英 | 2 席 | **离线** |

法语、日语没有直译译员，依赖英语中继（中→英→法 / 中→英→日）。初始状态下王一人扛起三个频道的中→英段，负载 3/3 满载。

### 演示脚本（故障 → 降级 → 恢复）

1. **主力离席**：在"译员席位表"把 **王（主力）** 切为离线。
   三个频道立即全部显示 `✕ 断路`，每个频道卡片列出原因——中继前段"中→英 无在线译员"，并提示可恢复的离线译员（王、陈）。调度日志同步记录中断事件。
2. **备援上岗**：把 **陈（备援）**（容量 2）切为在线。
   系统按优先级确定性分配：P1 英语频道恢复直译、P2 法语频道恢复中继；陈的 2 个席位用完，P3 日语频道显示 `⚠ 席位不足`，并指出瓶颈是"陈 席位已满（2/2），被英语频道、法语频道占用"。
3. **恢复全覆盖**：在"添加译员"表单加一名 **中 → 日** 直译译员（容量 1）。
   日语频道改为直译恢复收听，三频道全部 `✓ 正常`，顶部统计回到 `频道覆盖 3/3`。

随时可点顶栏"重置场景"回到初始状态。

## 译员交接协议（按语言通道 × 音频片段边界生效）

A 版本只有"配置态"路由表：主译员一断线，表上立刻换了人，但正在播的片段改派不下去（下一段还发给旧通道），旧译员恢复后又可能双发。交接版把每次路由变化变成一次有状态的交接：

| 阶段 | 音频行为 | 可观察信号 |
| --- | --- | --- |
| **准备 preparing** | 当前片段由旧通道完整播完，备援只热备不开声（图中虚线流动边 `◔ 热备中`） | 频道横幅 + 票据卡 + `准备` 轨迹事件 |
| **切换 switching** | 在片段边界**原子**完成：旧会话在边界关流，新会话自边界之后开声，区间左闭右开、恰好相接 | `⇄ 切换` 事件，轨迹带状图出现切换标记 |
| **确认 confirming** | 新通道出声，2 个片段内等备援确认；可点"手动确认" | 频道 `◉ 新通道确认中 n/2` |
| **回退** | 确认丢失/迟到超过截止（4 片段）且旧路可行 → 边界回退旧通道；旧路不可用则维持备援并告警 | `↩ 已回退`，事件记录回退原因 |
| **吸收/放弃** | 断线宽限边界（1 片段抖动缓冲）内主译员恢复 → 交接取消，同一会话连续在播 | `⊘ 已吸收`，无会话切换 |
| **静音 silenced** | 旧路失效且无备援/无席位 → 边界静音等待，恢复后下一边界重新开声（绝不段中起流） | 频道 `🔇 静音`、带状图 ✕ 格 |

### 核心不变量

- **同一直属频道任意片段至多一条在播会话**（`assertNoOverlap` 在测试中逐步校验）：切换是边界上的原子换边，不是"两条都播一会儿"；
- **在役粘滞**：仅仅"备援上线/出现更优路由"不触发交接，只有在役路由真正失效（译员离线或失去席位）才发起，避免抖动；
- **中继联动**：法语/日语频道的枢纽（中→英段）换人时，整条两跳路由随枢纽一起交接，席位按频道优先级在边界统一裁决；
- **故障幂等**：重复"主译重连"不重播、不双播；已切到备援后旧主返岗不抢通道，要切回必须再走一次完整交接。

### 演练控制

顶部"译员交接演练控制台"支持：

- **⏭ 单步推进**：推进一个音频片段，所有交接在其边界结算；
- **▶ 自动演练 / ⏸ 暂停**：常速 1.2s / 快速 0.55s 一片段，可随时暂停恢复；
- **故障注入**：`⚡ 主译短暂断线`（2 片段自动返岗，可被整段吸收）、`📶 主译重连`（幂等）、`🕐 迟到确认`、`✕ 确认丢失`、`🚫 备援离线`；
- **↶ 撤销 / ↷ 重做**：完整快照栈（最长 50 步），撤销后自动演练强制暂停；
- **刷新恢复**：片段号、生效路由、会话台账、票据与事件轨迹持久化到 localStorage，刷新后以暂停态恢复，可继续演练；
- **交接轨迹**：每个频道按片段的出声带状图（出声/静音/当前片段/切换标记）+ 近期交接结果胶囊 + 分阶段事件轨迹（准备/切换/确认/系统，倒序）。

## 路由规则

- **跳数上限 2**：频道可以直译（1 跳），或经过恰好一种中继语言（2 跳），更长的链不会被采用。
- **容量约束**：每名译员有席位数，每条路由在其每一跳上各占 1 席；任何译员负载不得超过容量。
- **优先级分配**：按频道优先级（数值小者优先，并列时按频道编号）依次贪心选路，高优先级先占用稀缺席位。
- **确定性**：候选路由按"跳数少者优先，同跳数按译员编号字典序"排序，同一输入永远得到同一分配结果，可复现、可解释。
- **循环拒绝**：自环译员（源=目标）永不可用；路由上的语种节点不得重复——不会回到主讲语言，也不会经过目标语言再继续。
- **断路诊断**：频道无可用路由时，指出每一处缺口（缺直译 / 中继前段断 / 中继后段断），并列出能补上该缺口的离线译员。

## 界面说明

- **交接演练控制台**（顶部）：片段号与运行状态、单步/自动/暂停/速度、撤销/重做/重置、五类故障注入、进行中票据卡（阶段、切换前后路由、手动确认）。
- **语种 · 译员连接图**（左侧）：语种为节点、译员为有向边，边上芯片实时显示 `负载/容量`。在役出声（蓝粗边 `🔊`）、热备待接（黄色流动虚线 `◔`）、空闲、满员、离线用不同线型加图标文字共同标示；频道芯片静音时显示 🔇；点击可高亮。
- **频道状态板**（右上）：配置态状态（`✓ 正常` / `⚠ 席位不足` / `✕ 断路`）+ **播放态**徽标（`🔊 播放中`/`🔇 静音`）、实际出声路由与起始片段、交接阶段横幅；可直接修改优先级。
- **交接轨迹**（右中）：每频道按片段的出声带状图、近期交接结果（完成/回退/吸收/静音）、带阶段标签与片段号的事件轨迹。
- **译员席位表**（左下）：增删译员、切换在线状态、修改容量（变更只挂"准备"，下一边界才改派音频），席位占用条带数字与纹理标示。

所有状态均以"图标 + 文字 + 线型/纹理"三重编码，不单独依赖颜色。

## 测试

`npm test` 运行 46 个测试。路由引擎（26 个，同 A 版）覆盖路径选择、容量竞争、优先级、循环拒绝、断路诊断与故障重路由；**交接引擎（20 个）**覆盖：

- **边界生效**：离线后段中不改派、宽限一次、第二边界原子切换（旧会话 `endTick` 恰等于新会话 `startTick`）、窗口内自动确认、中继频道随枢纽联动且席位不足者静音；
- **短暂断线 / 重连**：2 片段短断线被整段吸收（会话 id 不变）、断线期间手动提前重连取消交接、长断线切换后旧主返岗不抢通道、重复恢复信号幂等；
- **迟到确认 / 确认丢失**：超窗只告警不动音频、超截止且旧路可行才边界回退（会话边界相接）、旧主仍离线时维持备援不盲目回退、手动确认窗口语义；
- **备援不可达与恢复**：无双备援时宽限后静音、备援恢复后下一边界才重新开声（不段中起流）；
- **撤销 / 重做**：逐步回到切换前、重做重现切换、撤销强制暂停；
- **重复演练确定性**：同一复杂脚本演练两遍，会话台账、票据、事件轨迹（片段号+文案）完全一致；
- **刷新恢复**：localStorage 持久化后片段号/生效路由/会话/轨迹恢复且强制暂停，可继续推进；
- **全程互斥不变量**：断线/重连/迟到/回退/静音恢复/撤销重做交错的混合脚本，每一步后 `assertNoOverlap` 都成立。
