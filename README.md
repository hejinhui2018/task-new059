# 同传语言路由台

面向国际会议同传负责人的现场调度台。主讲人切换语种或译员临时离席时，调度台立即重算路由，直观显示哪些听众频道还能正常收听、哪些中断以及原因；译员交接按音频片段边界执行，全程可观察、可恢复。

全部数据在浏览器本地运行，无任何后端依赖。

## 快速开始

```bash
npm install        # 安装依赖（需要 Node.js ≥ 18）
npm run dev        # 开发模式，默认 http://localhost:5173
npm test           # 运行全部测试（vitest）
npm run build      # 类型检查 + 生产构建，输出到 dist/
npm run preview    # 本地预览生产构建
```

## 内置演示场景

打开即是预设会议：**中文主讲**，需要**英语、法语、日语**三个听众频道。

| 译员 | 方向 | 容量 | 初始状态 |
| --- | --- | --- | --- |
| 王（主力） | 中 → 英 | 3 席 | 在线 |
| 李 | 英 → 法 | 1 席 | 在线 |
| 佐藤 | 英 → 日 | 1 席 | 在线 |
| 陈（备援） | 中 → 英 | 2 席 | **离线** |

法语、日语没有直译译员，依赖英语中继（中→英→法 / 中→英→日）。初始状态下王一人扛起三个频道的中→英段，负载 3/3 满载。

### 演示脚本（故障 → 降级 → 恢复）

1. **主力离席**：在"译员席位表"把 **王（主力）** 切为离线（或在演练台点"✂ 王（主力） 断线"注入故障）。
   三个频道的目标路由立即全部显示 `✕ 断路`，每个频道卡片列出原因；同时演练台为每个频道发起"交接至静默"，**在下一片段边界**才停播——点"⏭ 单步"推进片段即可观察。
2. **备援上岗**：把 **陈（备援）**（容量 2）切为在线。
   系统按优先级确定性分配：P1 英语、P2 法语经交接切到陈；陈的 2 个席位用完，P3 日语频道目标为 `⚠ 席位不足`，在播转静默。
3. **恢复全覆盖**：在"添加译员"表单加一名 **中 → 日** 直译译员（容量 1）。
   日语频道经交接恢复直译收听，三频道全部 `✓ 正常`，顶部统计回到 `频道覆盖 3/3`。

随时可点顶栏"重置场景"回到初始状态（同时清空演练与本地存档）。

## 译员交接（片段边界 · 可观察 · 可恢复）

路由引擎算出的只是**目标分配**；真正发给听众的音频由**交接会话**管理。音频按片段（segment）推进，**每条频道任一片段至多一条在播路由，在播指针只在片段边界变更**——因此短暂断线、迟到确认、重复恢复都不会让两条通道同时播放。

### 交接生命周期

| 阶段 | 含义 |
| --- | --- |
| ⏳ 准备 | 目标与在播不一致，已发起交接，等待下一片段边界 |
| ⇄ 切换（待确认） | 边界已切到新路由，等待译员确认（自动确认开启时下一个边界自动完成） |
| ✓ 已确认 | 交接完成（终态） |
| ↩ 回退 | 确认超时或旧路由提前恢复：边界切回旧路由（旧路由不可用则转静默） |
| ✕ 已取消 | 准备阶段故障在边界前恢复，交接取消（在播从未离开原路由） |

- **确认窗口**：切换生效后 1 个片段内必须收到确认，否则超时回退。
- **迟到确认**：交接终结后到达的确认记入轨迹并忽略，不改变在播。
- **重复恢复**：同一恢复事件重复注入是幂等 no-op，不会产生第二个交接。
- **事件轨迹**：每次交接的发起、切换、确认、回退都按片段号记入"交接事件轨迹"，并镜像到调度日志；每片段每频道的派发记录（哪段音频发给了哪条路由）完整可查。

### 交接演练台

左栏下方的演练台驱动整个交接会话：

- **⏭ 单步**：推进一个片段（在边界应用待定的交接）；
- **▶ 自动演练 / ⏸ 暂停**：按 1.2 秒一片段自动推进，可随时暂停恢复；
- **演练脚本**：三个预设脚本——「主力瞬断与恢复」（含重复恢复注入）、「快速返岗回退与迟到确认」、「确认超时回退与恢复」；选"自由演练"则完全手动；
- **故障注入**：一键把任意译员置为断线/恢复（幂等置位，重复注入被忽略）；
- **自动确认开关**：关闭后新路由需手动"✓ 立即确认"，否则超时回退；
- **↩ 撤销 / ↪ 重做**：所有操作（注入、推进、确认、席位表修改）都可撤销重做；
- **⟳ 演练归零**：片段时钟回到 #1，各频道按当前场景重新开播；
- **刷新恢复**：场景、交接会话、演练进度与日志持续写入浏览器本地存储，刷新页面后完整还原。

## 路由规则

- **跳数上限 2**：频道可以直译（1 跳），或经过恰好一种中继语言（2 跳），更长的链不会被采用。
- **容量约束**：每名译员有席位数，每条路由在其每一跳上各占 1 席；任何译员负载不得超过容量。
- **优先级分配**：按频道优先级（数值小者优先，并列时按频道编号）依次贪心选路，高优先级先占用稀缺席位。
- **确定性**：候选路由按"跳数少者优先，同跳数按译员编号字典序"排序，同一输入永远得到同一分配结果，可复现、可解释。
- **循环拒绝**：自环译员（源=目标）永不可用；路由上的语种节点不得重复——不会回到主讲语言，也不会经过目标语言再继续。
- **断路诊断**：频道无可用路由时，指出每一处缺口（缺直译 / 中继前段断 / 中继后段断），并列出能补上该缺口的离线译员。

## 界面说明

- **语种 · 译员连接图**（左上）：语种为节点、译员为有向边，边上芯片实时显示 `负载/容量`。在役、空闲、满员、离线用不同线型（实线/加粗/虚线）加图标文字共同标示；点击频道卡片或图中频道芯片可高亮其路由。
- **交接演练台**（左下）：片段时钟、演练控制、故障注入、每频道交接状态卡（在播路由 / 目标路由 / 交接阶段）与交接事件轨迹。
- **频道状态板**（右上）：每个频道的目标状态（`✓ 正常` / `⚠ 席位不足` / `✕ 断路`）、**实际在播路由（自片段 N 起）**、交接阶段芯片、断路原因与处置建议；可直接修改优先级。
- **译员席位表**（右中）：增删译员、切换在线状态、修改容量，席位占用条带数字与纹理标示（满载为斜纹）。
- **调度日志**（右下）：译员上下线、频道中断/恢复、交接轨迹事件按时间倒序记录。

所有状态均以"图标 + 文字 + 线型/纹理"三重编码，不单独依赖颜色。

## 项目结构

```
src/
  types.ts               # 领域模型：语种 / 译员 / 频道 / 场景
  engine/routing.ts      # 路由引擎：候选路径、贪心分配、断路诊断（纯函数）
  engine/handover.ts     # 交接会话：片段时钟、在播指针、准备/切换/确认/回退状态机（纯函数）
  engine/drills.ts       # 演练脚本与逐步执行器（故障注入 / 自动确认 / 迟到确认）
  engine/*.test.ts       # 引擎与演练测试
  data/scenario.ts       # 内置演示场景
  ui/describe.ts         # 状态文案（图标+文字描述）
  components/            # GraphView / HandoverPanel / ChannelBoard / InterpreterPanel / EventLog
  App.tsx                # 命令管线（可撤销重做）、本地持久化、自动演练计时器
  App.test.tsx           # 渲染冒烟测试
```

## 测试

`npm test` 运行 49 个测试，覆盖：

- **路径选择**：直译优先于中继、中继语言记录、候选确定性排序、离线译员不参与、两跳上限；
- **容量竞争**：枢纽译员席位争抢、中继路由双段占座、容量耗尽时的瓶颈报告；
- **优先级**：高优先级先占席位、交换优先级后结果确定性地交换、并列时按编号定序；
- **循环拒绝**：自环排除、路由不回到主讲语言、路径节点不重复、往返译员拼不出伪路由；
- **故障与重路由**：内置场景全覆盖 → 主力离线全部断路并给出诊断 → 备援按优先级保住高优先级频道 → 增加直译恢复全覆盖 → 译员离线后确定性切换；
- **交接边界**：片段中途故障不改当片段派发、交接恰在边界生效、确认窗口与超时回退、静默交接无需确认；
- **断线重连**：边界前恢复则交接取消（在播从未离开）、跨边界断线切换后备援只服务其间片段、回退后迟到确认被忽略、确认完成后返岗走新交接；
- **重复事件**：重复对齐幂等、重复恢复不产生第二个交接、重复确认被忽略、同一操作序列两遍结果一致；
- **演练脚本**：三个预设脚本端到端轨迹、重复演练确定性、中途存档恢复后继续执行与一气呵成一致、全程每频道每片段恰一条派发（永不双通道同播）；
- **冒烟**：完整渲染调度台各面板与交接演练台。
